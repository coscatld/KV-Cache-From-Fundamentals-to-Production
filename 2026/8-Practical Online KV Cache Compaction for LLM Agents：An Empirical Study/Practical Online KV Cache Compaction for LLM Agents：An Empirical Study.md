# 脉络

### 1. 先前研究：Static Setting
生成前已知完整上下文，先对 KV Cache 进行离线压缩，再利用后续 Query 读取压缩后的缓存。此时，未来查询通常可以提前获得或通过离线方式近似。

### 2. 核心矛盾：Agent Online Setting

- 上下文动态增长： Agent 通过推理、工具调用和环境反馈逐步构建上下文，无法在任务开始时获得完整轨迹。
- 未来相关性未知： 压缩当前轮次时，无法准确预知未来轮次会读取哪些历史信息。
- 运行时预算受限： 压缩发生在 Agent 执行过程中，获取代理查询和执行压缩都会引入额外开销。

### 3. 研究内容：代理查询与在线压缩的交互

研究在 Agent 在线场景中，如何利用不同来源的代理查询指导 TE 和 AM：

- 代理查询来源： 当前轮次边界查询、重复预填充查询、后续轮次生成的 Query。
- 压缩时机： 立即压缩与延迟压缩；主要消融采用一轮延迟，另测试 3、5 轮。
- 压缩算法： 比较 TE 与 AM 在不同代理查询和压缩时机下的表现。
- 组合策略： 分析组合多个代理查询来源是否能够提升性能，以及额外信号何时会产生负面影响。

最终回答三个问题：

1. 哪种代理查询来源更有效？
2. 延迟压缩能否利用未来生成的 Query 改善任务性能，其收益是否值得额外的缓存占用和延迟？
3. TE 与 AM 对代理查询误差的敏感程度有何差异？

# 方法

当我们不知道未来 Agent 会用什么 Query 来读取历史 KV Cache 时，先找一个可用的 Query，近似代表未来的读取需求，用它指导 KV 压缩。

![[Pasted image 20261023112407.png]]
- 左：TE 和 AM 均使用代理查询对缓存 token 进行评分。TE 存储所选原始键和值，而 AM 保留所选键并优化注意力偏置和压缩后的值。
- 右：当前轮代理在轮次结束时可用，而未来轮代理将压缩推迟到后续轮次提供额外查询时进行。


### 1. 研究定位与压缩对象
这篇论文是**在线压缩设计空间的实证研究**：把已有 TE、AM 放入 Agent 循环，比较代理来源、压缩时机和缓存预算，而非提出一种新的压缩算法。

轨迹写成 $P,T_1,T_2,\ldots,T_t$：
- $P$：system prompt、工具定义与用户问题组成的初始 prefix，不压缩。
- $T_t$：该轮 assistant 生成（推理、工具调用等）及其工具返回。
- assistant 生成和工具返回分段压缩，保留聊天模板需要的结构边界 token。
- 压缩按层、按 KV head 独立执行；实验模型采用混合注意力，只处理 full-attention 层，其他状态保持不变。
- 一轮压缩后，原始 KV 被丢弃，压缩表示冻结，后续不再重新优化或重复压缩该轮。

来源：[§3–4.1](https://arxiv.org/html/2608.00902v1#S3)。

### 2. 三种代理查询：来源、成本与偏差
这里的 Query 指注意力层的查询向量，不是用户问题或搜索关键词。

| 来源 | 如何取得 | 可用时机与额外成本 | 主要局限 |
| --- | --- | --- | --- |
| Boundary | 提取结束或转折 token 的 Query，如 Qwen 的 `<\|im_end\|>` | 当轮结束即可使用，无需额外前向 | 结构边界的关注点未必代表后续任务需求 |
| Repeat-prefill | 追加重复提示，以 teacher forcing 重复已完成内容，提取重复部分的 Query | 可即时压缩，但需要额外前向计算 | “复述已有内容”与“未来使用内容”存在目标偏差 |
| Future generation | 保留目标轮原始 KV，收集后续轮 assistant 生成时的真实 Query | 延迟压缩；增加 Query 记录开销，并推迟缓存节省 | 近期未来仍未必覆盖更远期需求 |

Repeat-prefill 中，重复推理与工具调用产生的 Query 用于压缩 assistant 段，重复工具返回产生的 Query 用于压缩工具返回段。Future generation 默认仅使用后续 assistant 生成的 Query；加入工具返回 prefill Query 是额外消融。

论文没有测试 AM + 单个 Boundary Query：作者认为用单个 Query 拟合偏置和值，优化目标约束不足。这不等于 Boundary 在所有 AM 设计中都不可用。

来源：[§3.2、§4.2](https://arxiv.org/html/2608.00902v1#S3.SS2)。

### 3. 延迟一轮的完整时间线
1. **第 $t$ 轮完成：** 目标轮 $T_t$ 暂时保留原始 KV。
2. **生成第 $t+1$ 轮：** 模型同时读取初始 prefix、早期冻结的压缩轮和窗口内未压缩轮；记录 assistant 生成时的 Query。
3. **第 $t+1$ 轮完成：** 用收集的 Query 指导 TE 或 AM 压缩 $T_t$，释放其原始 KV。
4. **第 $t+2$ 轮开始：** 历史 $T_t$ 仅通过冻结的压缩表示被访问；对后续轮重复同一过程。

延迟 $k$ 轮时，收集 $T_{t+1},\ldots,T_{t+k}$ 的 Query 后再压缩 $T_t$。因此在线不等于立即：**延迟是在额外保留原始缓存的条件下，换取更贴近实际读取需求的信号。**

来源：[§3.2](https://arxiv.org/html/2608.00902v1#S3.SS2)。

### 4. 同一组代理，TE 与 AM 怎么用？
设代理矩阵 $Q\in\mathbb R^{q\times d}$，原始 $K,V\in\mathbb R^{n\times d}$，目标长度为 $m$。沿用论文记号，省略 $1/\sqrt d$ 缩放：
$$
\alpha=\operatorname{softmax}(QK^\top),\qquad
s_j=\sqrt{\frac{1}{q}\sum_{i=1}^{q}\alpha_{ij}^2},\qquad
S=\operatorname{Top}\text{-}m(s).
$$
- **TE：** 保存 $K_S,V_S$，原始条目的数值不变。
- **AM：** 使用相同的选 Key 过程，保存 $K_S$，再拟合偏置 $\beta$ 与压缩值 $V_C$。先匹配未归一化 Attention mass，再匹配 Attention 输出：
$$
\min_{\beta}\left\|
\exp(QK_S^\top+\beta)\mathbf 1_m-
\exp(QK^\top)\mathbf 1_n
\right\|_2^2,
$$
$$
\min_{V_C}\left\|
\operatorname{softmax}(QK_S^\top+\beta)V_C-
\operatorname{softmax}(QK^\top)V
\right\|_F^2.
$$
AM 多出的拟合自由度能改善代理 Query 上的匹配，但是否适用于未来 Query，仍取决于代理是否具有代表性。

组合多个代理源时，TE 按来源分配选 Token 预算；AM 对额外来源下采样后拼接为拟合 Query 集。两者的“组合代理”不是同一个操作。

来源：[§3.1、§4.2](https://arxiv.org/html/2608.00902v1#S3.SS1)。

# 实验证据

### 1. 基准与指标
- **BrowseComp-Plus：** 固定语料库中的多步检索问答，报告最终答案准确率。
- **WideSearch：** 开放网络中的广泛信息收集，输出表格，报告 item-level F1，兼顾事实正确性与完整性。
- 小模型主实验：Qwen3.5-4B、Gemma-4-E4B；另评估 Qwen3.5-27B、Gemma-4-31B。
- 主代理消融固定保留比例 $\rho=0.2$：指可压缩段缩短到原长度的 20%，不是整个运行过程的显存仅剩 20%。

来源：[§4.1–4.2](https://arxiv.org/html/2608.00902v1#S4)。

### 2. 代理来源与时机：Table 1 摘录
以下为 **Qwen3.5-4B、保留比例 0.2**。Turns 为轨迹轮数中位数；准确率和 F1 均按原表百分数尺度记录。

| 方法 / 代理 | 延迟轮数 | BrowseComp 准确率 | Turns | WideSearch F1 | Turns |
|---|---:|---:|---:|---:|---:|
| 不压缩 | — | 46.00 | 20 | 44.55 | 24 |
| AM / Repeat-prefill | 0 | 31.25 | 31 | 30.95 | 28 |
| TE / Repeat-prefill | 0 | 32.75 | 51 | 24.56 | 82 |
| TE / Boundary | 0 | 45.25 | 40 | 24.29 | 50 |
| AM / Future generation | 1 | 39.75 | 33 | 39.59 | 33 |
| TE / Future generation | 1 | 44.00 | 38 | 37.34 | 39 |

可以据此回答前面的三个问题：
1. **代理质量依赖任务。** Boundary 在 BrowseComp 上明显优于 Repeat-prefill，但在 WideSearch 上没有同样优势。
2. **延迟通常改善 Repeat-prefill，却不保证胜过所有即时策略。** BrowseComp 上，TE Boundary 的 45.25 高于延迟 TE 的 44.00。
3. **AM 没有稳定胜过 TE。** 上述延迟配置在 BrowseComp 上 TE 更高，在 WideSearch 上 AM 更高。不能仅凭拟合更复杂，就断言实际任务表现更好。

完整实验覆盖两个模型、两个基准；额外代理组合没有稳定收益。上表是点估计，95% bootstrap 区间见论文附录 Table 6，不应把小幅差异直接当成显著优劣。

来源：[Table 1 与对应分析](https://arxiv.org/html/2608.00902v1#S4.SS2)。

### 3. 延迟与预算的敏感性
论文比较延迟 $k\in\{1,3,5\}$，以及保留比例 $\rho\in\{0.1,0.2,0.4\}$。总体上，更多未来信号与更大保留预算有帮助，但收益不总单调，最佳设置随模型、任务、方法变化。

**阅读要点：** 延迟窗口与压缩预算应联合看待；更长延迟会保留更多原始轮，不能把质量收益单独归给代理更好而忽略缓存成本。

来源：[§4.3、Figure 2](https://arxiv.org/html/2608.00902v1#S4.SS3)。

### 4. 系统效率：真实任务轨迹 + Serving 模拟
Table 2 的准确率与轨迹来自 batch=1 的 Hugging Face 运行；吞吐由这些轨迹的 KV 长度、生成长度结合 SGLang 实测 decode 延迟进行回放模拟，**不是完整 Agent 在线部署的端到端实测吞吐**。

以下摘录 Qwen3.5-27B、BrowseComp-Plus，压缩均为延迟一轮、保留比例 0.2：

| 方法 | 准确率 | 平均轮数 | 峰值 KV 长度（千 Token） | 模拟 Serving batch | 模拟吞吐（任务/小时） |
|---|---:|---:|---:|---:|---:|
| 不压缩 | 52.50 | 18 | 612.9 | 8 | 217 |
| AM | 51.00 | 28 | 172.8 | 32 | 918 |
| TE | 52.00 | 31 | 175.2 | 32 | 717 |

吞吐收益同时涉及更短缓存和更高并发；不能将 AM 的 $918/217\approx4.2$ 倍解释为固定 batch 下单次 Attention 加速 4.2 倍。这里的峰值是 KV 长度口径，也不是整卡显存字节数。

来源：[§5.1、Table 2](https://arxiv.org/html/2608.00902v1#S5.SS1)。

### 5. 行为变化：正确率保住了，Agent 可能更费力
小模型结果中，Qwen 压缩后经常使用更多轮次。论文进一步发现搜索请求更重复，支持“Agent 可能通过再次检索补回受损信息”的解释。因此，最终正确率接近并不等于历史信息被完整保留。

评价在线压缩至少应同时看：**任务质量、轮数、工具调用与外部费用、代理获取与压缩耗时、峰值缓存、完整任务耗时和吞吐**。这些是建议的完整评估口径，不代表论文逐项完成了所有测量。

来源：[§5.2、Table 3](https://arxiv.org/html/2608.00902v1#S5.SS2)。

# 局限与研究切入点

### 1. 论文结论的适用范围
- 主要是搜索与资料收集 Agent；代码编辑、GUI 操作和有状态动作的相关性结构可能不同。
- 实验采用固定比例与固定延迟，尚未验证自适应控制策略。
- TE 的竞争力表明，代理不完美时，额外拟合不一定带来收益；但论文并未证明 AM 普遍劣于 TE。
- 原始轮一旦被压缩便不可恢复；即便某轮能匹配近期 Query，也不保证保留远期才需要的信息。

来源：[§6 与 Limitations](https://arxiv.org/html/2608.00902v1#S6)。

### 2. 本人的研究问题：能否按代理可信度决定何时压缩？
> 在同一峰值 KV 预算下，能否根据代理信号的稳定性与内存压力，动态选择“立即压缩、继续等待，或者提高该轮保留比例”？

这是从论文结果延伸出的研究设想，尚未验证。作者已将自适应策略列为未来方向，因此仅提出“动态延迟”不足以构成新颖贡献；需要具体、低成本的决策信号和可验证的收益。

可先尝试三个观察量：连续 Query 窗口的 Token 排名变化、候选保留集合的重合度、代理上的压缩输出误差。它们只能作为候选指标，不能默认能预测远期遗忘。

### 3. 最小验证实验
1. 固定一个模型和检索基准，以 TE 为起点，减少额外拟合带来的干扰。
2. 比较即时 Boundary、固定延迟 1/3/5 轮、同等预算的自适应策略。
3. 将“自适应时机”和“自适应保留比例”分别消融，避免同时改动后无法归因。
4. 在验证集选择触发规则，测试集固定规则；计入 Query 收集、统计与压缩开销。
5. 在相同峰值 KV 约束下，报告质量—总任务耗时关系，并记录重复检索和工具调用成本。

**要验证的核心假设：代理信号的变化能否预测“继续等待是否值得”，而不仅是解释压缩完成后的拟合误差。**
